# 主题预设 + 预设内配色编辑

## Context

应用的配色目前是硬编码的两套：`AppPalette.light` / `AppPalette.dark`，安装后无法更换，用户反馈这两套（暖琥珀 accent + 中性灰阶梯）都不满意。

我在 `design/palette-preview.html` 里做了四套完整色板供评审，用户选定 B（午夜靛）/ C（原名石墨素白，现名曜石）/ D（高对比）三套，并提出了两个新需求：

1. 把 B/C/D 做成**内置预设方案**，可以自由切换；
2. 每套预设都能**直接改颜色**，改动按预设各自保存。

> **2026-10 修订**：独立的「自定义」方案已移除。原先它是第 4 格哨兵 + 一份全局覆盖层（`nrs.themeCustom`），与「改预设」的直觉不符。现在三套预设各自带一份覆盖层（`nrs.themeOverride.<preset>`），编辑器始终编辑当前选中的那一套，「重置」只把那一套还原成出厂色。

目标产出：设置里一个「配色方案」选择器（3 套内置，每格右上角铅笔可编辑），加一个配色编辑器（取色 + 实时预览），选择与覆盖层持久化到 `shared_preferences`，重启后保留。

**已锁定的决策**（不再讨论）：只收录 B/C/D；默认（含老用户升级后）为 **C 曜石**；现有的琥珀色板退役，不保留；编辑器默认显示精选 12 个令牌、可展开看全部 25 个；取色器自研，不引入第三方包。

---

## 关键事实（先说清，避免踩坑）

- `AppPalette` 的 26 个构造参数里 `brightness` 是 `Brightness` 不是 `Color`，**可编辑颜色令牌 = 25 个**。
- `design/palette-preview.html` 底部的 `SCHEMES` 数组每套只有 **22 个** CSS 变量，**缺 `selectionEdge` / `shadow` / `overlay`**，这 3 个按 §2.4 的规则推导，不要手抄魔数。
- `AppPalette.light` / `AppPalette.dark` 这两个名字被 **12 个测试文件、25 处**引用。**保留名字、原地换成曜石的值**，使这些引用零改动继续有效（它们是「一个亮色板 / 一个暗色板」的通用夹具，不关心具体是哪套方案）。

## 1. `lib/core/theme/app_palette.dart`（改造）

### 1.1 新增 `AppPaletteToken` 枚举 + `TokenGroup`

25 个值，每个带中文 `label` 与 UI 分组，另加 `bool get hasAlpha`（仅 `selection` / `shadow` / `overlay` 为真，取色器据此决定是否露出 alpha 滑块）。

分 6 组：`surface`(5: canvas/sidebar/surface/surfaceRaised/surfaceSunken)、`line`(3: outline/outlineSoft/rule)、`text`(3: textPrimary/textSecondary/textTertiary)、`accent`(4: accent/accentHover/accentSoft/onAccent)、`status`(6: success/successSoft/warning/warningSoft/danger/dangerSoft)、`overlayLayer`(4: selection/selectionEdge/shadow/overlay)。

**用枚举 + 穷尽 switch，而不是 `copyWith` 加 25 个可空参数、也不是 `Map<String,Color>`**：枚举能挂元数据（label/group/hasAlpha）、`name` 天然是稳定线格式键、可被测试遍历，且将来新增令牌会在编译期同时打断读写与编解码——这是「新增令牌必须显式落地」的保证。

### 1.2 新增读写 API

```dart
Color colorOf(AppPaletteToken token) => switch (token) { ... };      // 25 支
AppPalette withToken(AppPaletteToken token, Color value);
AppPalette withTokens(Map<AppPaletteToken, Color> values);           // 未给的令牌保持原值
AppPalette _rebuild(Map<AppPaletteToken, Color> v);                  // 只走一遍构造器
static Color readableOn(Color background);                           // 取对比度更高的黑/白
```

`copyWith({Brightness? brightness})` **保持原样不动**，新 API 是纯增量。

`readableOn` 专治仓内 2 处 `p.isDark ? p.canvas : Colors.white`（见 §6），用 WCAG 相对亮度算，保证任意色板下实心状态块上的文字都读得见。

### 1.3 改写 `light` / `dark` 为曜石

值取自 `design/palette-preview.html` 的 `SCHEMES` 里 `id:'c'` 的 light/dark（22 个变量 → 22 个令牌），另外 3 个令牌按下节规则算出后**手抄成常量**（因为要保住 `const AppPalette.light`，测试里 6 处 `const AppPalette palette = AppPalette.light;` 依赖它）。

映射：`--canvas→canvas`、`--sidebar→sidebar`、`--surface→surface`、`--raised→surfaceRaised`、`--sunken→surfaceSunken`、`--outline→outline`、`--outline-soft→outlineSoft`、`--rule→rule`、`--t1→textPrimary`、`--t2→textSecondary`、`--t3→textTertiary`、`--accent→accent`、`--accent-hover→accentHover`、`--accent-soft→accentSoft`、`--on-accent→onAccent`、`--success→success`、`--success-soft→successSoft`、`--warning→warning`、`--warning-soft→warningSoft`、`--danger→danger`、`--danger-soft→dangerSoft`、`--selection→selection`。

同时删掉文件头注释里关于「暖琥珀 accent」的全部叙事，改成「多方案 + 预设内编辑」的说明，并写明一条团队规则：**只有 `AppPaletteContext.palette` 和 `ThemePresets.resolve` 有权决定「当前生效的色板」**，新代码不得直接调 `AppPalette.of(...)`（它现在的语义降级为「与主题无关的默认色板」，主要供测试夹具使用）。

## 2. `lib/core/theme/theme_presets.dart`（新建）

### 2.1 `ThemePresetId`

`obsidian('曜石', …, LucideIcons.gem)` / `midnight('午夜靛', …, LucideIcons.moonStar)` / `vivid('高对比', …, LucideIcons.zap)`。
`static const fallback = ThemePresetId.obsidian;`（**默认值放第一位，`values` 顺序即选择器顺序**）。图标一律用 `LucideIcons` 常量（项目规则：禁止 `Icons.*`）。

### 2.2 `ThemePreset` + `ThemePresets`

```dart
class ThemePreset { final ThemePresetId id; final AppPalette light; final AppPalette dark;
                    AppPalette paletteFor(Brightness b); }

abstract final class ThemePresets {
  static final List<ThemePreset> builtIn;                 // 3 套
  static ThemePreset of(ThemePresetId id);                // 未知 id → fallback
  static AppPalette resolve({required ThemePresetId preset,
                             required PaletteOverride? override,
                             required Brightness brightness});
  static PaletteOverride seed(ThemePresetId from);        // 编辑器起点
}
```
`obsidian` 直接复用手写好的 `AppPalette.light/dark`；`midnight`/`vivid` 用工厂函数构造（接 22 个具名参数，内部补 §2.4 的 3 个推导令牌）。`resolve` 拿到调用方为**当前预设**取出的覆盖层：有层用层，没层用内置。

### 2.3 `PaletteOverride`

一套预设的覆盖层：亮/暗各 **25 个绝对颜色**（不存 diff），因此自包含、不依赖「基于哪套方案改的」。字段 `light` / `dark` / `raw`（原始 JSON 串，用作 ThemeData 备忘键与脏检查）。方法 `withToken` / `withTokens` / `paletteFor(Brightness)`；`static decode(String? raw, {required ThemePresetId base})` —— 解不出返回 null，缺失的键兜 **`base` 那一套**的出厂值（不是曜石）。

### 2.4 三个推导令牌的规则

```dart
Color _selectionEdge(Color accent, Brightness b) => b == Brightness.light
    ? accent                                        // 与现有浅色实现一致
    : HSLColor.fromColor(accent)
        .withLightness((HSLColor.fromColor(accent).lightness * 0.86).clamp(0.0, 1.0))
        .toColor();                                 // 暗色下比 accent 更深

Color _shadow(Brightness b)  => b == Brightness.dark ? Color(0x66000000) : Color(0x14000000);
Color _overlay(Brightness b) => b == Brightness.dark ? Color(0x99000000) : Color(0x33000000);
```
仅暗面需要推导（亮面 edge 等于 accent）。B/D 两侧都由这套规则生成，实现后用测试断言具体 hex。

## 3. `lib/state/settings_controller.dart`（扩写）

新增 key：`nrs.themePreset`（`ThemePresetId.name`）、`nrs.themeOverride.<preset>`（每套一份 JSON 串）。**不改名 `nrs.theme`**——它承载 `ThemePreference`（system/light/dark），改名会丢掉老用户的明暗偏好。这两个轴是正交的：**配色方案**选色板，**明暗模式**选该色板的亮/暗面。

新增成员（形状照抄文件内既有 getter/setter 约定：读+兜底 / 早返回 / 写 / notify）：

- `ThemePresetId get themePreset` / setter（未知串 → `fallback`，不改写存储）
- `PaletteOverride? overrideFor(ThemePresetId)`（先看内存 draft，再看该预设自己的 key）
- `void previewOverride(ThemePresetId, PaletteOverride)` —— **只 notify，不写盘**（拖拽每帧用）
- `void commitOverride(ThemePresetId, PaletteOverride)` —— 落盘 + 清 draft（指针抬起 / 输入提交用）
- `void clearOverride(ThemePresetId)` —— 删掉那一套的 key，回到出厂色
- `void restoreTheme(({ThemePresetId preset, PaletteOverride? override}) snapshot)` —— 预设与该预设的覆盖层一起回滚（编辑器的「取消」）
- `AppPalette paletteFor(Brightness)` —— `ThemePresets.resolve(...)` 的薄包装
- `String get themeSignature => '${themePreset.name}|${当前预设的草稿或落盘}'` —— ThemeData 备忘键
- `bool themeEditing = false` —— 编辑期间让 `MaterialApp` 关掉主题补间

**为什么 preview/commit 要分开**：Windows 上每次 `setString` 都重写整个 prefs 文件，60Hz 拖拽 = 每秒 60 次文件写。draft 只活在内存，并记住它属于哪一套预设。

JSON 线格式：`{"v":1,"light":{"canvas":"fff7f7f5",…},"dark":{…}}`，颜色用 8 位小写 hex（含 alpha 字节，`toARGB32().toRadixString(16).padLeft(8,'0')`），解析 `int.tryParse(s, radix:16)`。体积约 800–900 字节，可忽略。

**前向兼容**：解码时缺失的键兜**所属预设**的对应出厂值，不认识的键忽略。这样将来新增第 26 个颜色令牌，老存档自动获得该预设的默认值、不会解码失败；`"v":1` 是给将来「令牌语义变更」留下的迁移钩子。

## 4. 接线：`lib/app.dart` + `lib/core/theme/app_theme.dart`

`app.dart` 是唯一接线点，把硬编码的两行换成：

```dart
final String sig = s.themeSignature;
theme:     _cachedTheme(sig, Brightness.light, () => AppTheme.build(s.paletteFor(Brightness.light))),
darkTheme: _cachedTheme(sig, Brightness.dark,  () => AppTheme.build(s.paletteFor(Brightness.dark))),
themeMode: s.theme.mode,
themeAnimationDuration: s.themeEditing ? Duration.zero : const Duration(milliseconds: 180),
```

- **主题备忘**：一个私有的 2 槽缓存（`(签名, 明暗) → ThemeData`），放在 `app.dart` 内部，不对外暴露 API。理由：`AppTheme.build` 含 `ColorScheme.fromSeed` + 25 个组件主题，而 `Consumer` 在每次通知上都会重建 `MaterialApp`；切方案时无所谓，但在编辑器里拖色是每帧通知，必须避免每帧重算两次。
- **补间开关**：`MaterialApp` 默认用 `AnimatedTheme` 对 `ThemeData` 做 lerp 过渡——切方案时是好效果（`AppPalette.lerp` 已经写好），但编辑时每帧都会重新起一段 200ms 过渡，手指和颜色之间会有黏滞感，且补间中的混合色板会让 `isDark` 短暂取旧值。所以编辑期间设 `Duration.zero`。

`app_theme.dart` 的 `build(AppPalette)` 签名不变，但要在 `ColorScheme.fromSeed(...).copyWith(...)` 里**补齐未覆盖的槽位**（`secondary/onSecondary/secondaryContainer/onSecondaryContainer/tertiary/onTertiary/surfaceContainerLowest/Low/surfaceContainer/surfaceContainerHigh/surfaceVariant/onSurfaceVariant/inverseSurface/onInverseSurface/scrim`）。否则任意用户强调色会让 `secondary` / `surfaceVariant` / `scrim` 等槽位漏出 seed 派生色（下拉菜单、次级按钮会串色）。

## 6. 影响面（让任意色板在全仓都成立）

**必须改的硬编码色（4 处遮罩 + 1 处阴影）**：`app_shell.dart:124`、`app_shell.dart:223`、`settings_dialog.dart:16`、`vault_tree.dart:546` 的 `Color(0x44000000)` → `p.overlay`；`vault_tree.dart:822` 拖拽预览投影 `Color(0xFF000000).withValues(alpha:0.30)` → `p.shadow`。

**必须改的状态色前景（2 处）**：`app_shell.dart:178`、`app_shell.dart:289` 的 `p.isDark ? p.canvas : Colors.white`（画在 `p.danger` 实心块上）→ `AppPalette.readableOn(p.danger)`。现有分支假设 danger 在暗色永远是浅鲑鱼，用户把 danger 调成深红时 `p.canvas` 落在深红上会直接读不出。

**有意保留的硬编码**（需补注释说明）：`title_bar_io.dart:146-147` 的 `_closeRed=0xFFC42B1C` / `_closeRedPressed`（Windows 标题栏关闭键的操作系统约定色，不属于应用色板，预览页的 `--cap-close` 同样写在 SCHEMES 之外）；`preview/code_palette.dart` 的 10 个语法高亮常量（代码配色按明暗分档而不是跟色板走是对的选择，**代价要如实承认：用户改了某套预设的颜色后，代码块颜色不变**，这个改进建议延后）；所有 `Colors.transparent`（是「无填充」不是主题色）。

**已核查的结论**：除上述 2 处 danger 前景外，全仓 14 处 `palette.isDark` 分支在任意色板下都仍然正确；`AppPalette.light/.dark/.of(` 在 `lib/` 下只有 2 处引用（`app.dart` 本次改掉，`app_palette.dart` 的兜底保留）。

**已知边角**：D 高对比的浅色面 `surfaceRaised == surface == #FFFFFF`（预览页有意靠 1px 描边而不是明度分档），所以该方案下 `note_list_panel` 里用 `p.surfaceRaised` 做 hover 的几行不会有可见变化。实测影响很小（列表行底色是 sidebar `#F4F4F5`，与白色有台阶）；若用户反馈，答案是在那几处改用 `surfaceSunken` 或 `accentSoft`，而不是回改方案值。

## 8. `lib/ui/theme/theme_editor_dialog.dart`（新建）

**非模态、居中、透明 barrier**——这是本方案的核心 UX 决定：

```dart
showThemeEditorDialog(context, preset: ThemePresetId.obsidian);
// showDialog(barrierColor: Colors.transparent, barrierDismissible: false)
// Dialog(alignment: Alignment.center, insetPadding: 24/24)
```
`maxWidth: 980, maxHeight: 760`。**绝不能照抄设置弹窗的 `barrierColor`**——那会把「左边看着真实应用实时换色」变成「看着一层灰膜」，实时写的价值直接归零。代价是编辑期间不能点击后方应用，这是主动接受的取舍。

```
Dialog(center) → Column
├ _Header        标题「编辑「曜石」」+「改动只影响这一套预设…」+ 关闭按钮
├ _BrightnessTabs   SegmentedToggle<Brightness>（浅色/深色）
├ Flexible(Row)
│  ├ Expanded(flex:3) → 滚动 Column
│  │   ├ _TierRow  SegmentedToggle<ThemeEditorTier>（简单 / 普通 / 高级，默认简单）+ 一行档位说明
│  │   ├ 简单 6：画布 / 侧栏 / 内容面 / 正文 / 次级文字 / 强调色
│  │   ├ 普通 12：表面 5 / 线条 3 / 文字 3 / 强调色（简单是其真子集）
│  │   └ 高级 25：再放出 状态 6 / 选区与浮层 4
│  └ Expanded(flex:2) → _LivePanel
│      ├ _MiniShellPreview(只吃传入的 palette，绝不读 context.palette)
│      └ 另一侧 12 色小色条 + 一行对比度读数
└ _Footer  「重置为内置」·「取消」·「完成」
```
`_TokenRow` 沿用设置弹窗 `_Row` 的语言：左色名 + 令牌名，中间 24×24 色块，右侧 `#RRGGBB`；点色块在该行下方手风琴式展开 `AppColorPicker`（一次只开一个）。

tab 选的是「编辑哪一面」，不是「现在显示哪一面」——跟随系统时用户可能在看着亮面改暗面，这点必须在标题区写清。

**强调联动**：在任一档位改 `accent` 时，同一次写入里一并推导并写回 5 个伴随令牌，否则用户在简单档只改 accent 会让主按钮文字停在旧 `onAccent` 上、可能直接读不出：

```dart
Map<AppPaletteToken, Color> deriveFromAccent(Color a, AppPalette p) => {
  accentHover:  _shiftLightness(a, p.isDark ? 0.10 : -0.10),
  accentSoft:   Color.alphaBlend(a.withValues(alpha: p.isDark ? 0.14 : 0.12),
                                 p.isDark ? p.surfaceRaised : p.surface),
  onAccent:     AppPalette.readableOn(a),
  selection:    a.withValues(alpha: p.isDark ? 0.30 : 0.20),
  selectionEdge: _selectionEdge(a, p.brightness),   // 共用 §2.4 的规则
};
```

**提交语义（实时写 + 抬起落盘 + 快照式取消）**：

- `initState`：`_preset = 传入的 preset ?? 当前方案`；记下 `_snapshot = (preset: _preset, override: overrideFor(_preset))`；`_working = snapshot.override ?? seed(_preset)`；`_tab = 当前 brightness`；`themeEditing = true`。**进入编辑器不写任何 key、也不产生覆盖层**，种子 == 该方案的值，视觉零跳变。
- 拖动中：`_working` 更新 → `setState` → `previewOverride(_preset, …)`（只 notify）；`onChangeEnd` → `commitOverride(_preset, …)`（落盘）。
- 「取消」：`themeEditing=false` + `restoreTheme(_snapshot)` → 预设与这一套的覆盖层一起回滚，其余两套从不被触碰。
- 「重置为内置」：只把 `_working` 换成 `seed(_preset)` 并 preview，**不写盘**；它在「完成」时才生效。
- 「完成」：若 `_working` 与该预设出厂板逐字节相同 → `clearOverride(_preset)`（不留下无意义的覆盖层），否则 `commitOverride`；然后 `pop`。`dispose` 兜底把 `themeEditing` 复位。

- **令牌往返**：对每个令牌 `withToken(0xFFFF00FF)` 后 `colorOf` 命中、且其余 24 个逐一不变（这是单 switch 抽象最强的证明）。

- 前向兼容：喂「未知 token 名 + 缺 `rule` + `v:2`」→ 未知键忽略、`rule` 落到**所属预设**的出厂值；喂 `'not json'` / `'{}'` → 返回 null。
- `resolve`：`(preset, null)` == 该预设内置；`(preset, seed(某套))` == 那套；覆盖层只对传给它的那套生效。
