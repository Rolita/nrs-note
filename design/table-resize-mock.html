范围

一次只拖一条内部竖线，改的是整列。最外侧的左右边线没有手柄；单列表没有可拖的线。

同一张表的所有行共享列宽，Markdown 里也没有「这一行单独宽一点」的表示。

规则

表格还有余量时，左列跟着指针变宽，表格一起变宽；到正文右沿后，再往右拖由右侧相邻列让位。

两列都不低于 64px。往左拖只收窄左列，右列不动；拖动中不实时重排。

源文件

宽度写在第一行第一格的 w= 里，单位是 15.5 号字下的设计像素，随字号和系统缩放等比缩放。

没有 w 就是自动列宽。项数不对、0、负数都会被忽略，表格退回自动。

提交与撤销

拖动期间不写文档、不记撤销；松手一次编辑、一步撤销。第一次拖动会把所有列固定成此刻的可见宽度。

之后内容变长只在列内换行，不再把列撑宽；想回到自动，删掉源文件里的 w= 键。

拖动公式

先长表格，再让邻列。拖动第 j 条线时，其它列完全不动。设左列宽 left、右列宽 right、全部列宽之和 sum、正文可用文字宽 room。

公式里的下限 MIN = 64；表格被窗口压缩时，同样按可见宽度计算，松手写回的是压缩后的宽度。

// 指针水平位移 dx，单位渲染像素
spare  = max(0, room - sum)
yield  = max(0, right - MIN)
left'  = clamp(left + dx,
               min(left, MIN),
               left + spare + yield)
sum'   = sum + (left' - left)
right' = right - max(0, sum' - room)

// 松手：渲染像素 → 设计像素
w[i] = round(px[i] / widthScale)

非目标（本轮不做）

拖最右边线单独改最后一列；拖动中的实时重排；侧栏的列宽按钮、重置按钮或宽度输入框；每一行独立列宽；转置时映射列宽；一次拖多条线；百分比/响应式列宽；键盘调宽。

为什么不做实时重排：现有行布局按「源码没变就复用」缓存；拖动中每帧改列宽会让整张表每帧重新测量、整篇文档重新排版，还会把每次鼠标移动记进撤销栈。第一版用落点线换零写入、零撤销记录和一次排版。
