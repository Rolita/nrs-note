回收站面板 · 4 套重构方案

现在的回收站是一个 680 宽的对话框，里面只有一条不加区分的笔记清单——文件夹被删掉之后，里面的笔记散成一排同样的行，看不出它们本来属于同一个文件夹，也看不出哪个是文件夹、哪个是文件。四套方案都按「原路径成组」重做：文件夹是一行可展开的组头，展开后才是它里面的笔记；根目录下的笔记单独成段。顶部可以切主题、亮暗、空/满两种状态，文件夹的箭头可以直接点开点收。

四套方案共用的规范

  • 分组：用 TrashEntry.originalPath 的父路径成组，不新增存储字段。同一路径下的条目并成一个文件夹组，组头显示条目数、合计大小、最近删除时间；子文件夹按路径前缀嵌套，最多缩进两级。
  • 区分：文件夹组头用 folder 图标 + 常亮箭头 + 500 字重；笔记用 fileText 图标 + 常规字重。根目录下的笔记不进任何组，单独一段「笔记库根目录」，与文件夹区分开。
  • 操作：每个文件夹组都能整组「恢复」或「永久删除」；单条同样可以。单条恢复仍然回到原文件夹，重名自动加「 2」。
  • 颜色：只用 surfaceRaised / surface / surfaceSunken / outline / outlineSoft / textPrimary / textSecondary / textTertiary / accent / accentSoft / danger / dangerSoft / overlay，不新增令牌。危险按钮的墨色按 AppPalette.readableOn(danger) 计算。
  • 几何：面板圆角 14、宽 680（B 700、D 占满窗口）；行高 27–30；间距走 4 / 8 / 12 / 16；字号 12.5 行 / 10.5 辅助 / 15 标题。悬停才出现的「恢复 / 永久删除」不占常驻宽度。

怎么挑

方案结构优点代价
A · 分组清单单栏，根目录段 + 文件夹组最紧凑，和左侧文件树同构，一屏看得最多列不对齐，时间/大小只能靠右挤
B · 文件夹卡片一张卡片 = 一个原文件夹分组边界最清楚，整组恢复最直观卡片留白多，条目少时显空
C · 双栏浏览器左树 + 右侧条目表最适合「先找文件夹、再挑条目」，像系统回收站每屏只能看一个节点，多一次点击
D · 底部表格抽屉窗口底部通栏，五列对齐不挡正文，批量核对路径/时间最舒服占屏幕下方，纵向只能放 7–8 行
